实际 dsh 的工具名是 `skill`，参数为 `{"name":"tdd"}` 这样的对象。文件提供器还会检查项目 `.dsh/skills`、`.agents/skills` 等覆盖来源，必须采用实际会话解析的版本；本轮没有创建任何项目覆盖。

安装版的部分 SKILL.md 带 `disable-model-invocation: true`，dsh 的 skill 工具会拒绝这些名称。已明确授权采用其方法时，worker 使用文件读取工具读取实际 SKILL.md 和相对引用文件，按项目规则执行，记为“文件加载”；也可使用真正的人类显式调用入口注入的说明。不得假记成功的 skill 工具调用，不移除禁用标记，不假设文中 `Skill` 或 `/name` 在每个宿主都可直接执行。没有文件访问或实际版本不可用时准确记录缺口。

## 开工与测试纪律

开始时按根 AGENTS.md 的阅读顺序读取当前范围、术语/相关 ADR 和前置证据。确认 predecessor 已 LOCKED，且实际工作分支包含其成果；标签或未合并 PR 不构成集成证明。需要合并才能获得前置成果时，等待协调会话完成已授权的合并与实际集成核查。

在 S 中写明允许范围、测试接口（seam）、固定输入及哈希、独立预期、命令、环境、证据、容差和受影响回归。已有授权及冻结决定继续有效，不因 skill 的通用访谈或确认步骤逐次增加普通开发审批门。确有影响实现/验收的未决信息时，只澄清该缺口，不重新访谈完整项目。

对新增业务行为采用一条失败测试 → 最小实现 → 验证的小步切片。测试面向调用方可观察行为；预期来自冻结规格、手工独立样例或独立答案，不能照抄实现算法。适当运行单项检查、类型检查与任务范围的完整检查；不把整批想象中的接口测试先铺开。

必要的浏览器、MCP、本地模型、Kafka、流引擎和持久化按所属阶段真实验证。测试使用实际依赖，禁止 Mock；上游原版测试、离线模型解析、构建成功或截图都不能替代项目硬验收。保留既有主动视觉/截图限制，浏览器验收采用 S 中明确的实际操作、数据和网络证据；若具体工具权限冲突，报告该缺口，不将必要验收改成可选。

缺陷/性能回归先运行可捕捉原始症状的反馈命令，保存原始失败；缩小原因后修复，保留失败、候选变化与受影响回归。不能通过改独立答案或放宽条件“修复”结果。

## 审查与准确版本

code-review 比较基准默认采用当前任务已记录的集成基准，记录其完整 SHA、实际 merge-base 与准确候选 C，使用固定的差异/提交范围覆盖当前任务全部变更，不能仅审查最近一次修复。规范与规格分别给出结论。检查未提交的应用、测试、依赖或行为配置，不能漏在 C 之外；存在这些改动时先形成新 C。

实际宿主支持子代理时，仅作只读的 Standards/Spec 并行审查，不增加开发 Ticket 或开发 worker；不支持时串行完成两个维度并说明。子代理也遵守相同根规则、比较基准和只读范围。审查/实测后修改应用、测试、依赖或行为配置，必须形成新 C 并重验受影响条款，保留旧失败。skills 通用“实现完成并提交”不是本项目完成定义。

## S→C→E→K 与人工合并

1. 读取当前任务和前置集成基线；由真实 worker 补齐并提交冻结记录 **S**，再开始实现。
2. 按适用 skills 实现当前任务，提交完整候选 **C**；对准确 C 作代码审查和必要真实验收。
3. 失败则修复、形成新 C 并重验；全部必要项 PASS 后形成证据提交 **E**，引用被测 C，登记 VERIFIED。
4. E 仅保存证据及必要登记，不夹带实现、测试、依赖、行为配置或验收语义变化；E 不填写 E 自身最终 SHA。
5. 核实远程 E 与指向 E 的基线标签，旧标签不得覆盖；再以状态提交 **K** 引用已知祖先 S/C/E 和核实结果，登记 LOCKED。K 不填写自身最终 SHA。
6. 推送 K，并在外部 Ticket 回执核实实际远程 SHA；交付 PR，协调会话在全部必要检查通过后完成最终核查与合并。
7. 确认下一任务实际工作分支包含所需前置成果后，继续依赖就绪任务。合并/冲突解决改变行为时，对新的实际集成版本重验。

必要 FAIL、BLOCKED、SKIP、NOT_RUN 全部阻止验收；TASKS.md 的勾选仅表示 LOCKED。修改锁定行为前先创建变更任务或显式 REOPEN，保留旧标签、失败与证据，执行受影响回归。提交、推送、PR、合并和集成可用性分别记录。

详细状态、交付约束和报告模板分别见 [AGENTS.md](../../AGENTS.md)、[REPORT.template.md](../../evidence/REPORT.template.md)。本轮 preparation 下的记录和未提交文档不得冒充 S、C、E、K 或正式验收。
