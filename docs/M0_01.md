# Vue 与 Python 独立运行

M0-01 提供 Vue 3/TypeScript 服务连接页面，以及 Python/FastAPI 健康接口。页面请求实际 API，显示服务名称、版本、状态和实例，连接失败时可重新检查。完整任务状态见 [TASKS.md](../TASKS.md)，冻结规则见 [criteria.md](../evidence/M0-01/criteria.md)。

## 本机开发

需要 Node >=22.12、npm、Python3.12 和 uv0.9.7。两端依赖分别由 [package-lock.json](../frontend/package-lock.json) 和 [uv.lock](../backend/uv.lock) 保存。所有命令从仓库根目录执行；临时目录必须处于本工作树的忽略目录：

```sh
mkdir -p .scratch-runtime/m0-01/tmp
export TMPDIR="$PWD/.scratch-runtime/m0-01/tmp"
export TMP="$TMPDIR"
export TEMP="$TMPDIR"
export UV_CACHE_DIR="$PWD/.scratch-runtime/m0-01/uv-cache"
uv sync --project backend --locked
uv run --project backend --locked uvicorn gt_lifecycle_api.app:app --host 127.0.0.1 --port 8201
```

另一个终端启动独立 web：

```sh
npm ci --prefix frontend
npm run dev --prefix frontend -- --port 5173
```

页面地址为本机5173端口，默认`/api/v1`经Vite代理到8201。Python只提供API，关闭web后健康接口仍可访问；关闭API后页面显示“连接失败”。点击“重新检查”再次发出HTTP请求；请求5秒超时。页面刷新和重新检查都会清除旧成功结果。

## 配置

| 配置 | 作用与默认值 |
| --- | --- |
| VITE_API_BASE_URL | 前端API前缀，默认`/api/v1`；支持同源路径或完整HTTP/HTTPS URL。Vite在启动/构建时读取，更换后重新启动开发进程或重新构建。空值、凭据、query/hash和其他协议被拒绝。 |
| API_PROXY_TARGET | Vite开发/preview反向代理的目标，默认`http://127.0.0.1:8201`，路径保留。 |
| API_INSTANCE_ID | Python实际服务实例标识，默认`local`，1～64个ASCII字母、数字、下划线或连字符。 |
| API_CORS_ORIGINS | Python允许的跨源origin，JSON字符串数组；本机默认5173/4175两个127.0.0.1 origin。容器默认空数组。禁止通配。 |
| API_UPSTREAM | 部署web的Nginx代理目标，默认`http://api:8000`；使用容器内DNS和真实HTTP。 |
| WEB_PORT / API_PORT | Compose发布的127.0.0.1端口，默认8280/8281，可按机器实际占用更换。 |

例如直接访问第二个API实例：

```sh
API_INSTANCE_ID=api-b uv run --project backend --locked uvicorn gt_lifecycle_api.app:app --host 127.0.0.1 --port 8202
VITE_API_BASE_URL=http://127.0.0.1:8202/api/v1 npm run dev --prefix frontend -- --port 5173
```

直接跨源使用显式API_CORS_ORIGINS。部署浏览器使用同源`/api/v1`，Nginx保留路径代理到api；前端静态页面不由Python托管。API响应`GET /api/v1/health`包括schema_version=`1`、service=`gt-lifecycle-api`、实际发行包version=`0.1.0`、status=`ok`和配置instance_id。这里的ok只表示本阶段HTTP服务可用。未知API返回404，错误HTTP方法返回405。OpenAPI由FastAPI实际生成。

## 构建与部署

```sh
npm run build --prefix frontend
uv build --project backend
uv run --project backend --locked pytest -q backend/tests
```

前端产物位于frontend/dist，Python发行包位于backend/dist，各自构建。前端preview入口为`npm run preview --prefix frontend -- --port 4175`。

[compose.yaml](../compose.yaml)仅包含当前阶段web/api，两者没有启动依赖。使用已有Docker Desktop WSL2 Linux引擎：

```sh
docker compose -p gtl-lab build
docker compose -p gtl-lab up -d web api
docker compose -p gtl-lab stop web
docker compose -p gtl-lab start web
docker compose -p gtl-lab stop api
docker compose -p gtl-lab start api
docker compose -p gtl-lab down
```

web单独启动时仍提供页面；API未运行时健康检查明确失败。Nginx按请求解析api域名，支持api稍后启动。静态页面路径刷新返回Vue入口，`/assets/`缺失资源返回404。两个镜像分别由 [前端Dockerfile](../frontend/Dockerfile) 和 [后端Dockerfile](../backend/Dockerfile) 构建，API镜像仅包含Python包及其依赖。

## 实际验收

准备实际Chrome156.0.8078.80与必要系统库，设置M0_01_CHROME和M0_01_UV为实际可执行文件。浏览器Unix socket需要较短TMPDIR；可以在用户目录建立指向当前工作树`.scratch-runtime/m0-01/tmp`的专用符号链接并设置TMPDIR/TMP/TEMP，内容仍保存在当前任务目录。禁止使用/tmp。Chrome共享库缺少时，从当前Ubuntu发行包取得libnss3/libnspr4/libasound2t64，在当前任务忽略目录用dpkg-deb解包并设置LD_LIBRARY_PATH；系统已安装同样库时直接使用。

```sh
python3 scripts/verify_m0_01.py --criteria 18a9210947e0114a8bbc6a10c8864701dfb8539e --candidate <C完整SHA> --output .scratch-runtime/m0-01/run-<唯一编号>
```

入口要求准确HEAD=C、工作树干净、冻结S和基准为祖先；分别安装、构建、运行真实HTTP进程、浏览器和容器，测试实际独立启停、地址切换、开发跨源/反代、部署路由、5秒超时、非法配置及恢复。持续页面测试通过`npm run test:lifecycle`实际启动、终止和恢复API，在同一页面依次验证成功、点击后的失败与旧字段清除、再次点击后的恢复；记录唯一页面导航和全部实际进程。Python wheel在全新环境按导出锁安装后启动，并按backend/tests/configuration_cases.json的58项独立预期逐项验证：合法HTTP/HTTPS、IPv6、端口和空允许列表；非法userinfo、通配、路径/query/fragment、协议、空白/控制字符、端口及JSON形状/类型；instance边界。每条命令保存实际退出码与expected_exit_code，必要错误命令预期退出1；实际请求/响应、DOM、控制台、进程生命周期和哈希保存在输出目录。工具只采集数据，不采集图片，不替换网络响应。

干净复现从准确C通过`git clone --no-local --no-checkout`建立当前工作树`.scratch-runtime/m0-01/clean-<C前12位>`，在clone中`git switch --detach <C>`，origin设置为唯一目标仓库，重新准备该clone内的TMPDIR和缓存，使用同一命令并添加`--clean`。不得共享node_modules或venv。正式入口结束时回收所创建的进程、浏览器和该次Compose服务；不会操作其他项目的服务。候选审查需要的常驻入口由外部回执单独管理。
